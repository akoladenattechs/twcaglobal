# Deployment Guide for twcaglobal.org

> **Read this whole file before starting.** It reflects the CURRENT architecture:
> all uploads go to Cloudflare R2; the database uses `utf8`/`utf8_unicode_ci` for
> compatibility with older MySQL (5.0+) and newer (8.x) servers alike.

## Architecture at a Glance

| Concern | Where it lives |
| ------- | -------------- |
| Code | Project root (`/home/twmaorgn/twcaglobal.org`) |
| Web root | `public/` (must be set as document root in cPanel) |
| **All uploads** (sermons, songs, covers, books, hero images, newsletter images, **brand logos**) | **Cloudflare R2 bucket `twca`**, served via `https://cdn.twcaglobal.org` |
| Config | `.env` (never committed) |

---

## Step 1: Change Document Root in cPanel

Laravel requires the **`public/`** directory to be the web root.

1. Log into **cPanel** → **Domains** → find **twcaglobal.org**
2. Click the **Document Root** setting (folder icon or "Edit")
3. Change the path from:

   ```text
   /home/twmaorgn/twcaglobal.org
   ```

   to:

   ```text
   /home/twmaorgn/twcaglobal.org/public
   ```

4. Click **Save** / **Change**

## Step 2: Verify PHP Version

1. cPanel → **Select PHP Version** (under Software)
2. Select **PHP 8.2 or higher** (the server currently runs 8.3.30)
3. Enable these extensions (check the boxes):

   `bcmath`, `ctype`, `curl`, `dom`, `fileinfo`, `filter`, `gd`, `hash`, `iconv`,
   `intl`, `json`, `mbstring`, `mysqlnd`, `openssl`, `pcre`, `pdo`, `pdo_mysql`,
   `simplexml`, `tokenizer`, `xml`, `xmlwriter`, `zip`

## Step 3: Configure `.env`

Use `.env.example` as the template. The values below are the ones that MUST be
correct on the live server:

```dotenv
# ── App ──
APP_NAME="TWCA Church"
APP_ENV=production
APP_DEBUG=false
APP_URL=https://twcaglobal.org
APP_KEY=base64:<generated by installer — do NOT reuse the local dev key>

# ── Database (get credentials from cPanel → MySQL) ──
DB_CONNECTION=mysql
DB_HOST=localhost
DB_PORT=3306
DB_DATABASE=your_actual_database_name
DB_USERNAME=your_actual_database_user
DB_PASSWORD=your_actual_database_password
# Critical: utf8 (NOT utf8mb4) for compatibility with older MySQL servers
DB_CHARSET=utf8
DB_COLLATION=utf8_unicode_ci

# ── Cloudflare R2 Storage (ALL uploads go here) ──
# Values from Cloudflare Dashboard → R2 → bucket "twca" → Manage R2 API Tokens
R2_ACCOUNT_ID=<account-id>
R2_ACCESS_KEY=<access-key>
R2_SECRET_KEY=<secret-key>
R2_BUCKET_NAME=twca
# Custom domain attached to the bucket (NOT the pub-xxx.r2.dev URL)
R2_PUBLIC_URL=https://cdn.twcaglobal.org

# ── Mail (Resend) ──
MAIL_MAILER=resend
MAIL_FROM_ADDRESS="no-reply@twcaglobal.org"
MAIL_FROM_NAME="${APP_NAME}"
RESEND_API_KEY=re_<your-resend-key>

# ── Newsletter ──
NEWSLETTER_PUBLIC_URL=https://twcaglobal.org
NEWSLETTER_WEBHOOK_SECRET=<long random hex — same value used by the sender>

# ── Sessions / CORS ──
SESSION_SECURE_COOKIE=true
# If a separate frontend domain calls the JSON API, list it here (comma-separated).
# Empty = same-origin (defaults to APP_URL).
CORS_ALLOWED_ORIGINS=
```

> ⚠️ Never copy the local `.env` — it contains your dev APP_KEY, R2 credentials
> and Resend key. Build the production `.env` fresh from `.env.example`.

## Step 4: Install / Migrate

### Option A — Fresh install with the wizard

1. Upload `install.php` **and `_schema-data.php`** to the project root
   (next to `artisan`)
2. **Pre-fill `.env.production`** with your full production config (DB creds,
   R2 keys, Resend key, newsletter secret, etc.) — see "Pre-filling the env"
   below. The installer uses it as its `.env` template.
3. Access **`https://twcaglobal.org/install.php`**
4. Follow the 4-step wizard:
   - **Step 1**: Server requirements check
   - **Step 2**: MySQL credentials (test connection inline)
   - **Step 3**: Site settings + super admin account
   - **Step 4**: Review and click "Install Now"
5. The installer writes `.env` (with a fresh `APP_KEY`), runs
   `php artisan migrate --force`, seeds roles/permissions, creates the admin
   user, saves site settings and writes the `storage/installed` flag.
6. Login at **`https://twcaglobal.org/admin/login`**

#### Pre-filling the env (`writeEnvFile` behavior)

`install.php` **always** rewrites `.env` during Step 4 from its template:

- If **`.env.production`** exists in the project root, it is used as the
  template and the wizard replaces only `APP_NAME`, `APP_ENV`, `APP_KEY`,
  `APP_DEBUG`, `APP_URL`, `ASSET_URL`, `NEWSLETTER_PUBLIC_URL`, and the
  `DB_*` values. **All other keys (R2, Resend, secrets) are preserved.**
- If not, it falls back to a minimal built-in template that **does not**
  contain R2 / Resend / secret keys — so pre-filling `.env` directly is NOT
  a reliable way to keep those values; use `.env.production` instead.

> ⚠️ Never pre-fill `.env` itself — the installer will overwrite it and the
> fresh `APP_KEY` it generates is what should be used in production.

#### Why `_schema-data.php`?

Migrations are the primary path, but `install.php` runs from the **web
server**, not a terminal. On shared cPanel hosting, `exec()`/`exec` is often
**disabled**, so `php artisan migrate` (attempts 1–2) may fail. In that case
the installer falls back to importing the embedded schema via raw PDO
(attempt 3), which needs `_schema-data.php`.

`_schema-data.php` is generated from the local database and contains:

- `EMBEDDED_SCHEMA_SQL` — all 49 `CREATE TABLE` statements, normalized to
  `utf8` / `utf8_unicode_ci`
- `EMBEDDED_MIGRATIONS_SQL` — the 84 `migrations` records so `artisan` knows
  what already ran (making later `artisan migrate --force` a no-op)

It is harmless if unused (`@require_once`), and essential if the CLI path is
blocked. **Regenerate it** with
`php _dev-tools/generate_schema_data.php` whenever migrations change.

### Option B — Existing database (re-deploy)

```bash
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

## Step 5: R2 Media URLs

Every upload stores its full `https://cdn.twcaglobal.org/...` URL in
`media.file_name`, and `Media::getUrlAttribute()` returns it as-is — there is
no legacy local-media handling. On a fresh install no migration is needed.

`_dev-tools/swap_r2_domain.php` exists only for migrating an *existing*
database that once used `pub-xxx.r2.dev` URLs — not needed here.

## Step 6: Post-Deployment Checklist

### 1. Set Up the Scheduler (Cron) — REQUIRED for newsletters

Scheduled newsletters run every minute via Laravel's scheduler.
cPanel → **Cron Jobs** (Advanced):

```text
* * * * * /usr/local/bin/php /home/twmaorgn/twcaglobal.org/artisan schedule:run >> /dev/null 2>&1
```

Adjust the PHP path (`which php`) and project path to match your account.
Without this cron, scheduled newsletter sends never fire.

### 2. Storage

Uploads live in R2, so **`php artisan storage:link` is NOT needed**. There are
no legacy local upload files to deploy — all media is served from the R2 CDN.

### 3. Queue Worker

Newsletter campaigns are queued (QUEUE_CONNECTION=database). On cPanel without
supervisor, run the queue via cron (every minute):

```text
* * * * * /usr/local/bin/php /home/twmaorgn/twcaglobal.org/artisan queue:work database --stop-when-empty --max-time=55 >> /dev/null 2>&1
```

### 4. Security Cleanup

After confirming everything works, **delete these from the server**:

- `install.php`
- `_schema-data.php` (embedded schema dump — sensitive, regenerate on demand)
- `phpinfo.php`
- `diagnostic.php`
- `generate-key.php` (if present)
- Any `_dev-tools/` scripts

They are a security risk on a live site.

### 5. File Permissions

```bash
chmod -R 755 storage bootstrap/cache
chmod -R 775 storage/framework storage/logs
```

## Troubleshooting

| Symptom | Likely Cause | Fix |
| ------- | ------------ | --- |
| White screen / 500 | PHP version too low | Select PHP 8.2+ in cPanel |
| 500 error | Missing/wrong `APP_KEY` | Re-run installer (it generates a fresh key) |
| 500 error | Wrong DB credentials | Check `DB_DATABASE`/`DB_USERNAME`/`DB_PASSWORD` in `.env` |
| 500 error | Wrong charset | Ensure `DB_CHARSET=utf8` and `DB_COLLATION=utf8_unicode_ci` |
| 500 error | File permissions | `chmod -R 755 storage bootstrap/cache` |
| Media won't load (browser blocks) | CSP `media-src` | Already handled — middleware derives it from `R2_PUBLIC_URL` automatically |
| Uploads 404 | Wrong `R2_PUBLIC_URL` | Must be `https://cdn.twcaglobal.org` (custom domain), not `pub-xxx.r2.dev` |
| Emails not sending | Missing `RESEND_API_KEY` | Set it in `.env`; restart php |
